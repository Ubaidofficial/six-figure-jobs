# pSEO Publishing Guide (GSC-Safe, Noindex-Safe)

This guide defines how to publish large pSEO batches without sending `noindex` URLs to Google Search Console.

## Objective

Publish high-intent, indexable pages at scale while preventing:
- `Submitted URL marked 'noindex'`
- duplicate intent/canonical drift
- thin-page index bloat

## Current Hard Safeguards In This Repo

1. Shared indexability gates in [`lib/seo/indexabilityGates.ts`](../lib/seo/indexabilityGates.ts)
- `MIN_COMPANY_INDEXABLE_JOBS = 3`
- `MIN_CITY_INDEXABLE_JOBS = 3`
- `MIN_COUNTRY_INDEXABLE_JOBS = 3`
- `MIN_REMOTE_ROLE_INDEXABLE_JOBS = 3`
- `MIN_ROLE_FILTER_INDEXABLE_JOBS = 5`

2. Sitemap alignment
- Country sitemap emits canonical location URLs from [`app/sitemap-country.xml/route.ts`](../app/sitemap-country.xml/route.ts): `/jobs/location/{country}`
- Browse sitemap no longer duplicates country/location country-family URLs in [`lib/seo/browseSitemap.ts`](../lib/seo/browseSitemap.ts)

3. Legacy canonical consolidation
- `/jobs/country/*` now permanently redirects to `/jobs/location/*` in [`app/jobs/country/[code]/page.tsx`](../app/jobs/country/%5Bcode%5D/page.tsx)

4. Role-filter robots safety
- `/jobs/[role]/[filter]` now applies an indexability gate for salary-filter pages in [`app/jobs/[role]/[filter]/page.tsx`](../app/jobs/%5Brole%5D/%5Bfilter%5D/page.tsx)

5. Daily scrape post-run production validator
- [`/.github/workflows/daily-scrape.yml`](../.github/workflows/daily-scrape.yml) now runs a production `seo:validate` step with retries to catch sitemap/robots mismatches early.

6. Stale job detail retirement
- Canonical `/job/*` URLs now 404 once a record falls outside the freshness window instead of lingering as `200 noindex`.

## Publishing Workflow (Required)

1. Generate candidate pages in bounded batches
```bash
npm run pseo:generate:playbook-batch -- --batch-size 100 --output .tmp/playbook-batch-001.json
```

2. Validate locally before merge
```bash
SITE_URL=http://localhost:3000 npm run start
SEO_BASE_URL=http://localhost:3000 SEO_FULL=1 SEO_STRICT=1 npm run seo:validate:strict
SEO_BASE_URL=http://localhost:3000 SEO_TEMPLATE_SAMPLE_TOTAL=20 npm run seo:sample
```

3. Merge only after `seo-gates` CI passes
- `seo-local-gates`
- `seo-production-proof` (on `main`)

4. Publish with controlled budget
```bash
DOMAIN_AGE_WEEKS=13 PSEO_ENABLED=true npm run publish:pseo-batch
```
- Keep daily/weekly caps from `scripts/publish-pseo-batch.ts`
- Do not override caps during recovery windows

5. Submit sitemaps, not individual URLs
- Submit only `https://www.6figjobs.com/sitemap.xml`
- Do not bulk "Inspect URL" thousands of times
- Let Google discover child sitemaps naturally from index sitemap

## GSC Submission Policy For Large Rollouts

1. Only submit sitemap-backed indexable URLs
- Never submit experimental, thin, or manually assembled URL lists.

2. Keep canonical families singular
- One intent family -> one canonical route pattern.
- Example: country intent should resolve to `/jobs/location/*`.

3. Roll out gradually
- Start with the highest-confidence sections first (high live-job density).
- Expand only when GSC coverage trend is stable.

4. Track reasons, not just counts
- Watch "Excluded by `noindex`", "Duplicate without user-selected canonical", and "Crawled - currently not indexed".

## Pre-Submission Checklist (Pass/Fail)

- No sitemap URL returns `noindex`:
```bash
SEO_BASE_URL=https://www.6figjobs.com SEO_SAMPLE_PER_SITEMAP=1000 SEO_STRICT=1 npm run seo:validate:strict
```
- No duplicate canonical families in sitemap output.
- All newly added route families have robots + sitemap thresholds aligned.
- All legacy aliases have 301/308 redirects to canonical URLs.

If any check fails, do not submit a new sitemap batch.

## Incident Playbook: If GSC Shows `Submitted URL marked 'noindex'`

1. Run validator immediately
```bash
SEO_BASE_URL=https://www.6figjobs.com SEO_SAMPLE_PER_SITEMAP=1000 SEO_STRICT=1 npm run seo:validate:strict
```

2. Classify impacted URLs
```bash
URL_FILE=.tmp_audit/gsc_urls.txt npx tsx scripts/classify-gsc-urls.ts
```

3. Confirm whether issue is:
- robots mismatch (page noindex but in sitemap)
- canonical mismatch (URL submitted but canonicalized elsewhere)
- stale URL family (legacy path still being submitted)

4. Fix route/sitemap alignment first, then resubmit sitemap index.

## Non-Negotiable Rules

- Never submit URL sets that are not generated by current sitemap routes.
- Never keep parallel canonical route families live for the same intent.
- Never force indexing on low-signal pages; let thresholds decide.
- Every rollout must pass `seo:validate` before and after publish.
