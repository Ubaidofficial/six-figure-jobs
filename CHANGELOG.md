- Added a regression test guarding the hreflang-on-noindex SEO rule (`__tests__/seo/hreflangNoindex.test.ts`). `buildSliceMetadata` is the only place the app emits hreflang (`alternates.languages`); it already gates emission on `allowIndex`, but nothing enforced it. The test asserts hreflang is present on indexable pages and absent on thin/deep-paginated noindex pages, so a refactor can't silently reintroduce GSC hreflang warnings.

The fallback (company website → logo) silently 401'd for every company without a stored `logoUrl`. Companies with a stored `logoUrl` were unaffected (those embed a working token). Also set `LOGODEV_API_KEY` to the publishable `pk_` key in Railway (a secret `sk_` key had been set, which the public image endpoint rejects).

Added a daily `Data Quality Guard` workflow (`.github/workflows/data-quality.yml`, 07:00 UTC + manual dispatch) that runs `audit:data-quality` against production so data drift is caught within 24h rather than only on Mon/Thu scrape runs. Added a `duplicate_apply_url` invariant to the guard.

- One-off data cleanup: expired 118 duplicate active jobs (multiple rows sharing the exact same apply URL — kept the most complete row per URL), expired 91 dead-end active jobs (no recoverable employer apply URL — url was null or an aggregator), and nulled the salary on 4 remote jobs with an unverifiable currency (AUD/SEK on remote roles with no country anchor). Active job count 10,382 → 10,173.

- Added a live-data quality guard (`scripts/audit-data-quality.ts`, `npm run audit:data-quality`) wired into the Scheduled Job Scraper workflow after the scrape completes. It fails the run if any invariant breaks: apply URLs pointing at aggregators or ad-redirect wrappers, retirement-plan amounts (401k/403b/457b) stored as salaries, inverted salary ranges, or validated salaries missing a currency. This catches data regressions from a bad scraper/source on every run instead of in production (complements the per-PR unit tests, which guard the parser/cleaner code paths).

- Fixed two salary-currency parsing bugs in `lib/normalizers/salary.ts`. (1) `extractNumbers` now strips US retirement-plan tokens (`401k`, `403(b)`, `457(b)`) before number extraction, so "Competitive comp and 401k" no longer yields a bogus $401,000 salary. (2) `detectCurrency` now picks the currency marker that appears *earliest* in the text instead of the first by array order — a description that states "USD 200,000–250,000 … AUD equivalent 320,000" now resolves to USD, not AUD (AUD/CAD/SGD precede USD/EUR/GBP in the pattern list, so array order mislabelled multi-currency bands). Real single-currency salaries (e.g. `A$180,000`) are unaffected. Note: stale salaries written by the older parser are not retroactively corrected by this change (the refresh path only fills missing salaries) — a separate re-validation pass is required to clean existing rows.

- Made JobPosting JSON-LD currency consistent with the displayed salary. Added `resolveSalaryCurrency()` in `lib/jobs/salary.ts` (for non-remote jobs it trusts the job's country over a possibly-mislabelled parsed currency; remote jobs keep the parsed currency) and used it in both `buildSalaryText` and `buildBaseSalary` (`lib/seo/jobJsonLd.ts`). ### Bug Fixes

* unbreak AI job-description enrichment (the bulleted summaries). `AI_ENRICH_MAX_OUTPUT_TOKENS` defaulted to 600 (and prod env was set to **220**) — far too small for the full enrichment JSON (oneLiner + snippet + ~6 responsibility + ~8 requirement + benefits bullets), so the model truncated mid-JSON and the job failed with "AI returned invalid JSON". That silently starved enrichment coverage, leaving jobs to fall back to the raw scraped description. Raised the code default to 1500 (verified to produce clean, complete bullets — e.g. a Coinbase Staff SWE posting rendered crisp "What you'll do / Requirements / Benefits" bullets incl. the real salary band). **Production must set `AI_ENRICH_MAX_OUTPUT_TOKENS=1500` in Railway** — the env value overrides the code default. Added `scripts/sampleDescriptionEnrich.ts` (no-write quality sampler).
* search understands multi-word and role queries. Two bugs made role-keyword search miss obvious matches: (1) when `parseSearchQuery` resolved a structured role (e.g. "ML engineer" → `machine-learning-engineer`), the raw phrase was *also* AND-ed as a literal title substring — so it required the text "ML engineer" verbatim and returned almost nothing; the raw keyword is now only applied when nothing structured matched. (2) The keyword was a whole-string substring, so "senior backend python" only matched if that exact phrase sat in one field. It now tokenizes into per-word AND matches across title/company/location/skills (stopwords + 1-char tokens dropped), so queries match by intent regardless of word order. Unit-tested (`queryJobsWhere.test.ts`).
* apply links never point at an aggregator. A read-only audit found **71 active jobs** (69 builtin + 2 weworkremotely) whose apply link pointed at the scraper site; `scripts/repairAggregatorApplyUrls.ts` nulled those so the button hides instead of sending users to a competitor board. ### Features

* phased indexing rollout (`INDEXING_PHASE` env var, defaults to `1`). Phase 1 silences 11 sitemap families (blog, browse, category, city, country, level, remote, skills, slices + 2 slice shards), letting only `sitemap-jobs`, `sitemap-company`, `sitemap-salary` ship URLs. Direct response from this audit: only the homepage was indexed despite Google crawling ~20k URLs — pushing thousands more crawlable pages made the "Crawled - currently not indexed" bucket worse, not better. Silenced families return 200 with an empty `<urlset>` and an `X-Indexing-Phase` header. Bump `INDEXING_PHASE=2` to re-enable.
* `scripts/pushPhase1ToIndexingApi.ts` — one-shot enumeration of the 105 Phase 1 URLs (hubs, top-10 role guides, role × top-5 country combos, top-20 priority companies) submitted to Google's Indexing API as `URL_UPDATED`. Run via `railway run` to seed the crawl queue after Phase 1 ships.
* phase-aware `noindex` on 11 pSEO route families so the next layer is defended even if Google reaches them via internal links: `/jobs/[role]`, `/jobs/[role]/[filter]`, `/remote/[role]`, `/salary/[role]/[...loc]`, `/jobs/skills/[skill]`, `/jobs/city/[city]`, `/jobs/level/[level]`, `/jobs/category/[category]`, `/jobs/state/[state]`, `/jobs/location/[country]`, `/jobs/industry/[industry]`. Each calls `isPhaseIndexable()` last, so a tier-1 role + tier-1 country combination is still indexable while every other variant emits `index: false`.
* extend phase-aware `noindex` to 7 more pSEO variants: `/jobs/[role]/city/[city]`, `/jobs/[role]/skills/[skill]`, `/remote/[role]/[location]`, `/remote/[role]/city/[city]`, `/remote/[role]/country/[country]`, `/jobs/visa-sponsorship`, `/jobs/no-degree`. The 4 single-country redirect pages (`/jobs/canada`, `/germany`, `/uk`, `/usa`) and 2 deep redirect pages (`/jobs/[role]/remote`, `/jobs/country/[code]`) don't need it — they 308 to a covered target.
* schedule `scripts/repairDescriptionSalaryOutliers.ts` to run automatically every Sunday at 09:00 UTC via new `.github/workflows/weekly-salary-repair.yml`. Manually triggerable with an `apply` toggle (defaults to `true` on the cron, supports dry-run via `workflow_dispatch`). The script always runs a dry-run preview first so the artifact log shows what was going to change even when the apply step fails.
* adopt `fetchWithBackoff` in BambooHR, SmartRecruiters, Recruitee, and Workable scrapers. These four had zero or only blind linear retry, ignored `Retry-After`, and dropped every job on the company they were scraping when throttled. Each now goes through the shared util — same `Retry-After`-aware backoff Greenhouse uses. The 6 ATS scrapers still on the old loops (ashby, lever, breezy, teamtailor, workday, icims) have your in-progress changes; they remain a follow-up.
* failed ATS companies now requeue with a cooldown instead of being retried every run. `scripts/dailyScrapeV2.ts` stamps `lastScrapedAt` on failure (rotating broken companies to the back of the queue) and a configurable `ATS_FAILURE_COOLDOWN_MINUTES` (default 60) blocks retries until the cooldown elapses. Companies that have never been scraped are unaffected.
